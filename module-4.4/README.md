# Module 4.4 — SPI BME280

ESP32-S3 читає температуру, вологість і атмосферний тиск із BME280 через
апаратний SPI та показує їх на SSD1306 разом із часом і датою DS1307.
Це продовження `module-4.3`. DS18B20 у цьому варіанті не використовується.

## Підключення

Номери в таблиці — **номери GPIO**, а не порядкові номери контактів плати.

| BME280 / HW-611 | ESP32-S3 | Сигнал |
|---|---|---|
| VCC | 3V3 | Живлення 3,3 В |
| GND | GND | Спільна земля |
| SCL / SCK | GPIO12 | SPI SCK |
| SDA / SDI | GPIO11 | SPI MOSI |
| SDO | GPIO13 | SPI MISO |
| CSB / CS | GPIO10 | SPI CS, активний LOW |

Зовнішні перемички `CSB → 3V3` і `SDO → GND` зі старого I²C-підключення
потрібно прибрати. Лінії даних BME280 більше не з'єднані з GPIO8/9.

DS1307 та OLED залишаються на спільній I²C-шині, 100 кГц:

| Сигнал | ESP32-S3 |
|---|---|
| SDA | GPIO9 |
| SCL | GPIO8 |
| GND | GND |

Очікувані адреси: DS1307 — `0x68`, SSD1306 — `0x3C` (також перевіряється
`0x3D`). EEPROM Tiny RTC за адресою `0x50` програма не використовує.
Зберігається підключення живлення RTC з попереднього проєкту: DS1307 — 5 В,
OLED — 3,3 В; підтяжки SDA/SCL на стороні ESP32 — до 3,3 В.
Після перенесення BME280 підтяжки I²C мають залишитися; внутрішні підтяжки
ESP32 у коді вимкнені.

## Як працює програма

- BME280: SPI2, mode 0, 1 МГц, апаратний CS. Під час запуску перевіряється
  `chip ID=0x60`; BMP280 не підходить, оскільки не вимірює вологість.
- Драйвер Bosch читає заводське калібрування температури, тиску та вологості.
  Використовується normal mode, oversampling ×1 для всіх каналів,
  standby 250 мс, IIR-фільтр вимкнений.
- Кожні 500 мс програма одним SPI-блоком читає всі 8 байтів вимірювань.
  Компенсація виконується драйвером Bosch; тиск переводиться з Pa у hPa.
- Період задається монотонним `esp_timer_get_time()`. Зміна часу через `TIME`
  не впливає на частоту опитування.
- Немає `delay()` та циклу очікування завершення вимірювання. Датчик виконує
  вимірювання автономно. `xTaskDelayUntil()` віддає процесор іншим задачам
  між перевірками міток часу; callback `startup_wait()` потрібен лише під час
  ініціалізації/скидання Bosch, а не під час регулярного зчитування.
- OLED і `ESP_LOGI` отримують одні й ті самі відформатовані рядки кожні 500 мс.
  T і P мають один знак після коми, RH округлюється до цілого відсотка.
- Великі години/хвилини, секунди, дата та прогресбар збережені з module-4.3.
  До шрифту додані `%` і знак градуса; UTF-8 `°` займає одну позицію на OLED.
- Помилка BME280 прибирає числові показники з екрана. Через 5 секунд програма
  повторює ініціалізацію. Відсутність датчика не зупиняє RTC та UART.
  Без OLED дані продовжують надходити в лог.
- RTC записується тільки командою `TIME`, його значення не скидається при старті.

Приклад розміщення (ілюстративні значення):

```text
       15:33:59
    Sat 14.11.2026
T:23.4°C RH:45%
P:1013.2 hPa
██████████████████
```

Приклад рядка логу, а не запис фактичного вимірювання:

```text
I (...) module_4_4: 15:33:59 | Sat 14.11.2026 | T:23.4°C RH:45% | P:1013.2 hPa
```

## Збірка та запуск

PlatformIO: `espressif32 @ 7.1.3`, ESP-IDF 6.1.0,
оточення `esp32-s3-devkitm-1`. Конфігурація плати використовує 8 МБ flash.
Код Bosch включений у репозиторій; окреме завантаження бібліотеки під час
збірки не потрібне. `sdkconfig.esp32-s3-devkitm-1` генерується ESP-IDF.

Виконувати з каталогу `module-4.4`:

```powershell
pio run
pio run -t upload
pio device monitor
```

Якщо `pio` відсутній у PATH, для цього комп'ютера:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run
```

У `platformio.ini` встановлено `COM6`, 115200 бод, 8-N-1, LF,
локальне відображення введення та надсилання після Enter. Якщо номер порту
змінився, змінити `upload_port` і `monitor_port`. Перед прошиванням закрити
інші програми, що використовують COM6.

Встановлення часу через **Monitor Task** (не Upload Task):

```text
TIME 2026-11-14 15:33:59
```

Ввести потрібний місцевий час і натиснути Enter. Очікуване підтвердження:
`RTC set to ...; oscillator started.` Якщо після відключення живлення RTC
знову зупиняється, перевірити його резервне живлення.

## Перевірка на платі та демонстрація

1. Після прошивання перевірити в логу `chip ID=0x60` і `T/RH/P enabled`.
2. Перевірити час, дату, прогресбар, T, RH, P, `%` та `°` на OLED.
3. Звірити числові показники й час на екрані з відповідним рядком логу.
4. За мітками `I (...)` перевірити інтервал приблизно 500 мс; під час штатної
   роботи між оновленнями має бути не більше 1 секунди.
5. Перевірити реакцію температури/вологості на зміну умов біля датчика.
6. Надіслати `TIME`, перевірити підтвердження, хід секунд і збереження часу
   після перезапуску ESP32.
7. Окремо перевірити старт без BME280: екран має показати `BME280 ERROR` та
   `T/RH/P UNAVAILABLE`, а час і обробка команд мають продовжувати працювати.
   Зміни проводки виконувати при вимкненому живленні.
8. Зняти відео реального OLED і Serial Monitor. Додати його до GitHub або
   вставити посилання в цей README. Демонстрація ще потребує запису на платі.

Для здачі використати існуючий репозиторій `learning-embedded` і коміт,
наприклад `module 4.4: BME280 SPI weather display`, потім подати посилання
на GitHub у LMS.
